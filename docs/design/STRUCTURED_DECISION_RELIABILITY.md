## Existing REQUEST contract

Source of truth: `crates/scope-ide/src/agent_loop.rs` (`PROTOCOL`, `Decision`, `parse_decision`, `run_session`); adapter: `crates/scope-ide/src/agent.rs`. This is the ordinary decision runner, not the separate edit lifecycle in `edit_lifecycle.rs`.

The system instruction begins:

```text
You are a Scope assistant. Return exactly one JSON object, with no markdown or surrounding text:
{"type":"tool","name":"registered.tool.name","arguments":{"input":"value"}}
or {"type":"complete","content":"final answer"}.
```

It then specifies only listed tools, host authority to deny calls, supported argument types, one tool call per decision, JSON `tool_result` data in user messages, correction using feedback, truthful reporting of denied/failed calls, no ambient shell/filesystem/build access, and completion when done or when capabilities are missing.

The initial user message is a serialized envelope containing `kind=request`, the request text, and the installed tool catalog. Each assistant decision is retained verbatim, including malformed text. Successful calls and tool errors become serialized user-role `tool_result` envelopes. There are no native OpenAI function calls here.

Accepted decision alternatives:

```json
{"type":"tool","name":"registered.tool.name","arguments":{"input":"value"}}
```

```json
{"type":"complete","content":"final answer"}
```

These examples are contract examples, **not live-model observations**. The tagged Serde enum denies extra fields; required fields and their types must match. Tool names and completion content must be nonblank. Arguments must be an object, with recursively supported null, boolean, signed 64-bit integer, string, array, and object values. Duplicate argument keys, floats, and out-of-range integers are rejected. A proposed call still passes through session lookup, argument validation, and host policy; a decision is not authorization.

### Validation and correction

`parse_decision` uses `serde_json::from_str::<Decision>` directly. It does not extract fences, select an object from prose, or repair JSON. Empty/EOF errors are `incomplete_response`; other deserialization errors (including schema/type failures) are `malformed_response`; blank names/content are `invalid_decision`. Thus `malformed_response` alone does not distinguish invalid JSON from valid JSON with the wrong schema. Capture the exact parser error and independently assess JSON syntax without dispatching or replacing the strict parser.

Correction feedback includes `kind=protocol_error`, category, detailed error, and this instruction:

```text
Return one valid decision object matching the system protocol. No tool was dispatched; retained tool results remain authoritative.
```

The host's error prefix is `Invalid model decision protocol (not a language diagnostic): ...`, not the quoted downstream paragraph. The runner never manufactures a natural-language completion after exhausting malformed responses: it returns a non-completed stop with empty content.

Default limits: 12 decisions, 8 tool attempts, 2 malformed corrections, 64 KiB per message, 256 KiB conversation content, 1,500 requested output tokens per decision. Malformed decisions consume decisions. The third malformed decision stops without further feedback. Limits are cumulative, not reset by successful tools. Denied/unknown tool attempts count; transport failures return errors rather than adding a hidden Scope retry. Byte limits stop rather than truncate. No automatic rollback occurs after an executed tool.

### Instruction review

The examples are valid and mutually exclusive; no contradictory example was found. The protocol already explicitly requires one object and one call per decision. Remaining usability opportunities are explicit JSON string escaping and explicit prohibition of additional keys/arrays/multiple decisions, currently enforced by the parser but not all spelled out in the prompt. The placeholder tool/argument example can only be interpreted using the actual catalog. The dense safety/feedback paragraph adds reading load but carries real authority distinctions. None of these observations demonstrates that prompt ambiguity caused the latest failure.

## Backend capability assessment

Scope pins Cell tag `v0.0.1`, lock revision `9609d9e2cb22718187388d6a4f803ff6b97eed64` (`Cargo.toml`, `Cargo.lock`). Inspection of that locally cached dependency found:

- `crates/capability-openai/wit/openai.wit`: chat request exposes messages, optional temperature, optional max tokens.
- `crates/capability-openai/src/lib.rs`: serialized `OpenAiChatCompletionsRequest` contains model, messages, temperature, max_tokens only; POST target is `/chat/completions` under the configured base URL.
- No `response_format`, JSON-object mode, JSON-schema mode, or native function-call request field exists on this path.
- Cell selects the first choice's message content; Scope's `DecisionModel for CellAgent` retains only content. Finish reason and other choices are not available to the ordinary runner. Temperature is 0.2.

This agrees with `HARNESS_GUIDE.md`: current Cell chat accepts text messages, not server-enforced schemas. **Client omission is not evidence that LM Studio rejects or supports any optional response format.** The actual server version, model capability, and optional-feature behavior were not probed.

JSON-object mode, if supported, could constrain syntax for both tool and completion envelopes but would not establish the tagged schema, registered tool arguments, or authorization. JSON-schema mode could constrain both decision alternatives if the server supports the necessary union and schema subset; tool-specific argument schemas and integer/duplicate-key behavior need separate evaluation. Neither mode replaces host parsing or policy.

Native support requires extending the Cell request boundary and exposing an explicit optional capability/configuration on the Scope backend path. The generic text `DecisionModel` interface need not become model-specific. An unsupported backend must retain the strict text protocol when structured mode was not selected; explicit structured-mode failures must not silently downgrade mid-run. Any future fallback policy should be host-selected and tested, not inferred from model names or arbitrary error strings. This investigation does not implement that broader API work.

## Regression tests and validation

`crates/scope-ide/src/agent_loop_tests.rs` adds deterministic cases for literal unescaped newlines, concatenated objects (including a tool-first payload), fenced JSON, surrounding prose, extra fields, and non-object arguments. Each fails strict validation, produces protocol correction, and dispatches no tool before a subsequent valid completion. Escaped newline content remains accepted. A separate test verifies the default third-malformed stop has empty content and zero dispatches.

Validation performed:

- `cargo test --offline -p scope-ide --features agent --lib agent::decision::tests`: **14 passed**, including both new tests; no model/network calls.
- `cargo fmt --all -- --check`: passed.
- An initial `agent_loop` test-name filter matched zero tests; it was replaced by the module-qualified command above, not counted as validation coverage.

These tests establish strict rejection, correction routing, and budget behavior only. They do not measure model reliability or prove prompt improvements.

## Recommendation and remaining uncertainty

Keep production unchanged. First capture the actual failing run; then test the narrowly scoped escaping/single-object clarification. Adopt it only with matched evidence of improvement and unchanged host validation. Structured output is a potential independent backend enhancement, not a correction already supported by the pinned abstraction.

Unresolved: actual raw latest decision/request; syntax versus schema versus truncation; number of inspections before failure; provenance of the displayed paragraph through the downstream host; backend optional-feature support; effect of the increased context limit; final-answer semantic accuracy; and comparative model reliability. No Scope implementation defect or latest-run root cause has been established. Reported historical unescaped newlines are consistent with model noncompliance with JSON syntax, but do not classify this newer run.
